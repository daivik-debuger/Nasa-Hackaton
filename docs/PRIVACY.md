# Pilot privacy and data-flow inventory

## Current behavior

| Data | Where it goes | Intended storage |
|---|---|---|
| Map viewport, browser network metadata, and site origin | The satellite view requests visible-area tiles from Esri World Imagery; the street view requests tiles from OpenStreetMap. Requests occur when the map opens or moves, even before **Load available data**. Either provider can see the approximate viewed area and an origin-only referrer | The app does not intentionally save tile requests or cache tiles in its service worker. Browser HTTP caches and provider logs are outside our control |
| Field coordinates and selected period | Browser request to NASA POWER; browser request to this app's `/api/imerg` when a reference day is available; `/api/soil` only for the Central Iowa demo. The server forwards requested coordinates to NASA GPM IMERG or USDA Soil Data Access as applicable | The app does not intentionally save these requests |
| Local account name, email and password | Sent only to this app's same-origin Node server when a user creates an account or signs in | Name/email and a salted scrypt password hash are stored in `.local-data/farmers.json` (or `FARMER_DATA_PATH`). The raw password is not stored. An HttpOnly, SameSite=Strict session cookie expires after 12 hours; sessions live only in server memory |
| Farm name, exact coordinates, selected historical period, crop history, priorities, optional soil texture/laboratory pH, and optional Global Plan form inputs (elevation, manual climate class, SOM, water estimates and three crop phases) | Used in the current page; sent to the same-origin account API only when the signed-in user presses **Save current farm** or **Update saved farm** | Stored per account in the same local file until the user deletes that saved farm. The file is ignored by Git and created with owner-only permissions. There is no automatic save |
| Optional public-example conversation link | Created only when a labeled city-area example is selected and the user presses Copy. The URL contains only that example ID, selected years, and one predefined question. The app does not include a private map pin, field name, crop notes, or soil values | Anyone receiving the link can open that public example; the app does not store a conversation or send the link to a server by itself |
| Public app files, source/crop/evidence JSON | Browser and service-worker app-shell cache | May remain on the device until cache removal |
| Interface fonts | Uses the device's built-in system font stack | No third-party font request |

The local prototype now has account sessions and a per-account saved-farm file, but no hosted database, email verification, password reset, encrypted data-at-rest, backup policy, account deletion UI, or production security audit. Account API routes are disabled when the server binds publicly (`HOST=0.0.0.0`). It is **not ready for real farmer information on a public host**. A user can delete individual farm records in Farmer view; full account deletion requires a future supported workflow and local administrator action. Do not manually remove someone else's account file. Sessions end on sign-out, server restart or 12-hour expiry. A judge/research URL exposes only public evidence and the user's current unsaved page state; it does not grant access to saved farms from other accounts. The selected workspace and theme are presentation preferences, not authorization boundaries.

API query strings can appear in browser history, reverse-proxy logs, hosting logs, or upstream-service logs. Public-example links also appear in the recipient's history and may appear in logs. We have not audited a production host or third-party retention policies. NASA/soil/IMERG responses are not stored with saved farm records; the user must request observations again.

The map is optional for precise location entry: **Exact coordinates** remains available if the map library or tiles fail. The default satellite view uses [Esri World Imagery](https://www.arcgis.com/home/item.html?id=10df2279f9684e4a9f6a7f08febac2a9), and the street view uses OpenStreetMap, with visible attribution and ordinary browser caching. The app does not export tiles or prefetch them for offline use. The [Esri imagery item](https://www.arcgis.com/home/item.html?id=10df2279f9684e4a9f6a7f08febac2a9) says the layer is not intended for offline tile export; [OpenStreetMap's tile-use policy](https://operations.osmfoundation.org/policies/tiles/) requires a valid browser referrer and offers no service-level guarantee. The server uses `Referrer-Policy: strict-origin-when-cross-origin`. A production deployment should review both providers' terms, attribution, and capacity. The imagery basemap is visual context, not a measured crop-health or soil indicator.

## Before collecting real farmer data publicly

- Decide whether precise coordinates are necessary, and offer a clear explanation before transmission.
- Choose a retention period, deletion process, and access policy for any saved field data.
- Review provider terms, third-party telemetry, logs, and backup retention.
- Use managed persistent storage, HTTPS, account recovery, account deletion/export, abuse protection, backup/retention policies, monitoring, and a security review. Render's default filesystem is not a durable farmer database.
- Add a privacy notice and consent flow appropriate to the actual deployment and jurisdiction. The current local-prototype warning is not a substitute.
